## 1. 现状：实测出来的 11 个问题

### 1.1 字号：13 种散落值（79 处声明），最小 9px —— ✅ 已修（U-B1）

`app.css` 里 `-fx-font-size` 出现 **79 处声明、13 种不同值**，其中 **3 种在 12px 以下**（11 / 10 / 9）。
**现已收敛为 9 档阶梯**（`fs-2xs` 10 / `fs-xs` 11 / `fs-sm` 12 / `fs-md` 13 / `fs-lg` 14 /
`fs-xl` 16 / `fs-2xl` 20 / `fs-3xl` 32 / `fs-4xl` 40），并由 `AppCssAuditTest` 守着：

| 字号 | 出现次数 | 典型落点 |
|---|---|---|
| 12px | 32 | 表格正文、按钮、菜单 |
| 11px | 21 | 提示文字 |
| **10px** | **9** | 功能栏文字、侧栏分组标题、**列类型行**、排序角标、**状态栏**、命令面板提示 |
| **9px** | **3** | 方言角标、标签脏标记、标签关闭钮 |
| 14px | 4 | 图标按钮 |
| 13px / 15px | 2 / 2 | 输入框、对话框标题 |
| 12.5px | 1 | ← **孤例**，没有理由存在 |
| 17 / 18 / 26 / 34 / 60px | 各 1 | 空状态、对话框大标题 |

**问题**：
- **9px 低于任何可读下限**（macOS 最小 11px，Windows 最小 9px 但已不推荐）。
- **10px 承担了 9 处关键信息**：状态栏、列类型行、功能栏标签 —— 这些是用户**每一眼都在看**的地方，
  恰恰是最不该最小的。
- **没有字号令牌**：改一次字号要翻 CSS 找 32 处。

**已修**：
- 9px **全面废除**；10px 只留给**单字符徽标 / 角标**（徽标、排序角标、脏标记、快捷键角标）。
- 状态栏、列类型行、功能栏文字、分组标题 **一律升到 11px**。
- 12.5px 孤例删除；欢迎页大标题 60px → 40px；页面标题 18px → 16px。
- 9 档字号进 `tokens.json`（`fs-*`），`AppCssAuditTest` 断言 CSS 里不得出现阶梯外的字号。

### 1.2 间距：47 种硬编码内边距（68 处声明）—— ✅ 已修（U-B2）

`-fx-padding` 出现 **68 处声明、47 个不同值** —— 从 `0`、`2 4`、`4 10` 一路到 `16 18`、
`0 16 8 16 48`。

**问题**：没有 4px 阶梯。同类的「按钮内边距」就有 `4 10` 和 `3 8` 两种，
所以两个视觉上同类的东西**高矮不一样**；而 47 个不同值意味着**没人能记住哪处该用哪个**。

**已修**：收敛为 **7 档 4px 阶梯**（`sp-1` 2 / `sp-2` 4 / `sp-3` 8 / `sp-4` 12 / `sp-5` 16 /
`sp-6` 24 / `sp-7` 32）；按钮内边距统一 `4px 12px`，图标按钮 `4px 8px`，输入框 `4px 12px`；
CSS 里全部带 `px` 单位（原来是无单位的 `4 10`），才能和令牌逐字对上。

### 1.3 圆角：5 个硬编码值，无规则 —— ✅ 已修（U-B2）

`-fx-border-radius` 出现 **26 处声明、5 个不同值**（**3 / 5 / 6 / 8 / 10**），**没有令牌**。

**问题**：10px 的圆角（对话框）配 6px 的圆角（按钮）在同一屏上显得
「外框比内框还圆」——这是典型的层级没设计。

**已修**：收敛为 **3 档 + pill**（`r-sm` 3 / `r-md` 5 / `r-lg` 8 / `r-full` 999），
并按**角色**分派：控件 5、面板 8、小元素 3、**徽标与标签片 999（药丸形）**。
`AppCssAuditTest` 断言外层圆角 ≥ 内层圆角的那套档位。

### 1.4 令牌：60 个里 40 个是颜色，**字号 / 间距 / 圆角根本没有令牌**

```
tokens.json 共 60 个：
  颜色 40  ·  高度 4（h-toolbar/h-tabbar/h-statusbar/h-input）
  宽度 4（w-sidebar-*） ·  行高 3（row-*） ·  时长 3（dur-toast*）
```

**问题**：`A17` 令牌收敛做完了「**没有死令牌**」，但没做「**该有的令牌没有**」。
颜色体系其实是这套设计系统里**做得最好的部分**（40 个语义色、亮暗两套、风险四级齐备），
**排版 / 间距 / 圆角三层则完全靠手写**。

### 1.5 交互态：18 条 hover，**只有 3 条 focus** —— ✅ 已修（U-B3）

| 状态 | 规则数 | 覆盖 |
|---|---|---|
| `:hover` | **18** | 按钮、图标钮、功能栏、树、标签、筛选钮、chip、面板列表项、危险钮、Toast 动作… |
| `:focus` | **3** | `.menu-item:focused`、侧栏搜索框、网格搜索框 |

**问题**：**鼠标能看见焦点，键盘看不见**。
`adb-button` / `adb-icon-button` / `.adb-object-tree .tree-cell` / `.adb-tab` /
`.table-cell` / 通用输入框 —— **全部没有 focus 环**。
纯键盘操作的用户无法知道自己在哪。这是可访问性硬伤，不只是好不好看。

**已修**：focus 规则 **3 → 29 条**，覆盖按钮 / 图标钮 / 功能项 / 树 / 表格 / 标签 /
输入类 / 列表 / 滑块。做法是「边框换主色 + 一圈光晕」，
**刻意不改边框宽度** —— 宽度一变，获得焦点时控件会大 1px 抖一下。

### 1.6 按钮：数据网格工具栏 11 个按钮，**10 个长得一模一样**

```
保存      → adb-button--primary   ← 唯一有层级
刷新 / 结构 / 新增行 / 撤销 / 重做 / 筛选 / 清除条件 / 列 / 视图 / 导出
         → adb-button--ghost      ← 全部：透明底 + 透明边 + 次级文字
```

**问题**：
- ghost 的定义是「透明底 + 透明边」→ 与背景融成一片，11 个按钮在屏幕上是一条**灰色文字带**，
  没有分组、没有主次、扫视成本极高。
- **没有分隔线分组**：浏览 / 编辑 / 视图三类动作混排。
- 数据页实际有 **18 个动作**，工具栏平铺 10 个 —— 宽度不够时只能挤。

### 1.7 禁用态用 `opacity` 整体压暗 —— ✅ 已修（U-B3），但**根因比想得更深**

```css
.adb-button:disabled {
    -fx-background-color: -adb-bg-disabled;
    -fx-opacity: 0.45;          /* ← 整个节点一起淡 */
}
```

**问题**：opacity 会**同时稀释文字和图标**，禁用按钮变成「几乎看不见」，
和「可点击但没反应」难以区分。而 `text-disabled` 令牌**已经存在**却没被用在这里。

> ⚠️ **实测踩到的更深一层**：把我们的 `-fx-opacity: 0.45` 删掉之后，
> **Modena 给所有 `:disabled` 控件加了 `-fx-opacity: 0.4`**
> （javafx-controls 的 `modena.css`「DISABLED THINGS」段）——
> 于是按钮**更**看不见了。
> 数据页的「保存」按钮整个消失（截图里只剩一片空白）。
>
> **真正的修法**：显式把禁用态的透明度**还原成 1**，禁用感完全由颜色表达
> （底色 `bg-disabled` + 文字 `text-disabled` + **保留边框**）。
> 门禁：`FocusRingAuditTest.disabledControlsNeutraliseModenasOpacity`
> + `DisabledButtonVisibilityTest`（3 例，已验证能抓到回归）。

### 1.8 图标：Unicode 符号与中文词**混用** —— ✅ 已修（U-B4）

```
符号类：◈ ⌨ ▦ ⇅ ◆ ⇤ ⇥ ↻ ✕ ＋ ▽ …
中文词类：关闭 ×3  重试 ×3  打开 ×3  复制 ×3  删除 ×3  保存 ×3  筛选  编辑  清除 …
```

**问题**：
- **同一排按钮里既有符号又有中文词**，视觉重量完全不同（符号 ~14px，中文词两三个字 ~36px）。
- 中文词当图标 → 一排按钮宽度忽宽忽窄，无法对齐。
- 符号依赖系统字体，**跨平台字形不一致**（`⌨` 在 macOS 和 Windows 上完全不是一个样）。
- Navicat 用的是一套**统一描边的矢量图标**，宽度、高度、笔画粗细全部一致。

**已修**：
- 新增 `io.agenticdb.ui.Icons`：**38 个手绘 SVGPath 矢量图标**，
  统一 16×16 视框、1.5px 描边、圆头圆角；颜色由 CSS 的 `.adb-icon` 接管 →
  **切主题时图标自动跟着变**。
- 按钮里的 Unicode 符号**一个不剩**（功能栏、标签栏、对象树、工具栏、分页器、
  连接页、结构页、导入导出、命令面板、状态栏的脏标记…）。
- 领域层（`ObjectKind`）**不再带图标** —— 图标是 UI 的映射，领域不该知道图标长什么样。
- 工具栏改成 **Navicat 形态的图标条**（纯图标 + Tooltip + accessibleText），
  原来 11 个「图标 + 文字」的按钮把工具栏撑爆、文字被压成「…」。

> ⭐ **顺带发现的真问题**：图标按钮的文字被压成「…」。
> 根因不是图标太大，而是**工具栏 11 个「图标+文字」按钮的总宽超过了可用宽度**，
> JavaFX 于是把每个按钮压到只剩省略号。
> 解法不是「把图标画小」，而是**把工具栏改成图标条** —— 这才是 Navicat 的形态。

### 1.9 密度：只覆盖数据网格与对象树 —— ✅ 已修（U-B5）

`setFixedCellSize` **只出现在 `DataGridPage`**。

| 界面 | 跟随密度？ |
|---|---|
| 数据网格 | ✅ |
| 对象树 | ✅ |
| **查询结果网格** | ❌ |
| **表清单页** | ❌ |
| **连接管理列表** | ❌ |
| **结构页的索引 / 外键 / 触发器三张表** | ❌ |

**问题**：用户在数据页调到「紧凑」，切到查询结果页行高没变 → 密度设置**看起来时灵时不灵**。

**已修**：**4 处**同步 —— 数据网格 / 查询结果网格 / 表清单 / 结构页的四张表
（外加连接表格）。行高取自 `row-*` 令牌，经 `io.agenticdb.ui.RowHeights` 统一换算。

### 1.10 连接管理页是 `ListView`，不是表格 —— ✅ 已修（U-B5）

```java
private final ListView<ConnectionProfile> list = new ListView<>();
```

**问题**：一个连接占一行，`名称 + 主机/库/用户` 挤在两行文字里。
Navicat 用**表格**：名称 / 主机 / 端口 / 数据库 / 用户 / 状态，每列独立，
可排序、可按列筛选、横向可拖列宽。当前实现**连列都没有**，用户要靠点开每个连接才知道连的什么。

**已修**：改成 `TableView`，**7 列**（名称 / 类型 / 主机 / 端口 / 数据库 / 用户 / 状态），
每列可排序；双击一行 = 打开；收藏标记放进「名称」列（不另开一列）。

### 1.11 列头噪音：每列都挂**常显**筛选按钮 —— ✅ 已修（U-B5）

```java
Button funnel = new Button("▽");   // 每个列头都挂一个，永远可见
```

**问题**：
- 12 列的表 → **12 个 `▽`** 挂在表头上，视觉噪音压过列名本身。
- Navicat 的做法是**悬停列头才浮现**筛选图标，常态只有列名 + 排序箭头。

**已修**：常态 `-fx-opacity: 0`（**仍然占位**，浮现时列名不会顶来顶去），
悬停列头才浮现；**该列有筛选条件时一直可见**（那是状态，不是装饰）。

## 2. Navicat 基准：我们要对标成什么样

> 只列**本项目范围内**的形态。首版明确不做的（ER 图、计划任务、传输同步…）见 §9。
>
> ⚠️ **基准的来源**：Navicat 的界面形态取自对该产品的了解与使用经验，
> **不是**在本机截取的 Navicat 真实截图（本机没有 Navicat）。
> 而「当前形态」一列的每一条都来自**本仓库的实测**（`app.css` / `tokens.json` / 源码扫描 / 6 张真实窗口截图）。
> 若要更严格的对标，需要在装有 Navicat 的机器上补一组并排截图 —— 列为可选任务，不阻塞开工。

### 2.1 整体 UI/UX

| 维度 | Navicat 形态 | 当前形态 | 差距 |
|---|---|---|---|
| 顶栏 | **大图标 + 文字**的功能区（连接 / 查询 / 表 / 工具） | ✅ 同形 | 低 |
| 侧栏 | 连接列表（可排序表格）+ 对象树 + 底部搜索 | 对象树 ✅ / 连接列表是文本行 ❌ | **中** |
| 主区 | 标签页，标签带**类型图标** | 标签带文字 + 脏标记 ⚠️ | **低** |
| 数据页 | 工具栏 + 记录导航条 + 表格 + 底部分页器 | 工具栏 + 表格 + 底部分页器 | **中** |
| 状态栏 | 左：连接/库；右：行数/耗时/事务 | ✅ 同形 | 低 |
| 主题 | 亮 / 暗 / 跟随系统 | ✅ 同形 | 低 |

### 2.2 按钮

| 维度 | Navicat 形态 | 当前 | 差距 |
|---|---|---|---|
| 层级 | primary（实心蓝）/ default（描边）/ ghost（无框）/ danger（红） | 四档**都存在** ✅ | 低 |
| 视觉权重 | ghost 仍有底色 + 弱边框，扫视成组 | ghost **完全透明** → 11 个按钮一条灰字带 | **高** |
| 分组 | 工具栏按语义用分隔线分组 | 无分组 | **中** |
| 命中区 | 图标按钮 ≥ 28×28 | 约 28×28 ✅ | 低 |
| 禁用 | 保留形状、文字变灰 | 整体 opacity 0.45 → 几乎不可见 | **中** |

### 2.3 字体

| 维度 | Navicat（macOS） | 当前 | 差距 |
|---|---|---|---|
| 界面基准 | 13px | 12px | 中 |
| 表格正文 | 12–13px | 12px | 低 |
| 辅助文字 | 11px | 11px ✅ | 低 |
| 角标 / 徽标 | 10–11px | 9px / 10px | **中** |
| 字体族 | 系统 UI 字体 | 需确认（见 §4） | — |

### 2.4 配色

| 维度 | Navicat 形态 | 当前 | 差距 |
|---|---|---|---|
| 主色 | 单一蓝 | 单一蓝 ✅ | 低 |
| 风险色 | 绿 / 黄 / 红 / 紫 四级 | ✅ 四级齐全 | **无差距（强项）** |
| 亮暗双套 | ✅ | ✅ 60 令牌齐全 | 低 |
| 焦点环 | 每个可聚焦控件都有 | **只有 3 处** | **高** |
| 遮罩 / 阴影 | 对话框有遮罩与投影 | 无遮罩令牌 | 中 |

### 2.5 交互

| 维度 | Navicat 形态 | 当前 | 差距 |
|---|---|---|---|

## 4. 排版规范

| 令牌 | 值 | 用途 | 允许出现的地方 |
|---|---|---|---|
| `fs-2xs` | 10px | 徽标、角标 | **仅单字符徽标** |
| `fs-xs` | 11px | 辅助信息 | 状态栏、列类型行、树副标题、提示文字 |
| `fs-sm` | 12px | 密集正文 | 表格单元格、按钮、菜单、树节点 |
| `fs-md` | 13px | **界面基准** | 面板标题、输入框、次要说明 |
| `fs-lg` | 14px | 区块标题 | 分组标题、对话框小标题 |
| `fs-xl` | 16px | 页面标题 | 空状态标题 |
| `fs-2xl` | 20px | 强调标题 | —— |

**硬规则**：
1. **9px 禁止出现**；10px 只允许单字符徽标。
2. 任何新界面**不得**写字面量字号，只能引用 `var(--adb-fs-*)`。
3. 字体族统一 `-fx-font-family: "System"`（JavaFX 会解析成系统 UI 字体），
   不用硬编码 `"SF Pro"` / `"Segoe UI"` —— 跨平台才不炸。

## 5. 间距规范

| 令牌 | 值 | 用途 |
|---|---|---|
| `sp-1` | 2px | 图标与文字 |
| `sp-2` | 4px | 紧凑元素间隙、chip 内边距 |
| `sp-3` | 8px | 控件内边距（图标按钮 `4 6`）、分组内元素间隙 |
| `sp-4` | 12px | 面板内边距、按钮内边距（`5 12`） |
| `sp-5` | 16px | 区块之间 |
| `sp-6` | 24px | 大区块之间 |
| `sp-7` | 32px | 空状态上下留白 |

**硬规则**：所有间距是 **4 的倍数**（`sp-1` 除外，仅用于图标微调）。

## 6. 圆角规范

| 令牌 | 值 | 用途 |
|---|---|---|
| `r-sm` | 3px | 徽标、输入框、小图标钮 |
| `r-md` | 5px | 按钮、菜单、下拉 |
| `r-lg` | 8px | 卡片、面板、对话框 |

**硬规则**：**外层圆角 ≥ 内层圆角**。对话框 8 > 按钮 5 > 输入框 3 ✅

## 7. 配色规范

现有 40 个颜色令牌是**这套设计系统最强的部分**，保留。补 3 个：

| 令牌 | 亮 | 暗 | 用途 |
|---|---|---|---|
| `overlay` | `rgba(31,35,40,.45)` | `rgba(1,4,9,.6)` | 对话框背后的遮罩 |
| `shadow-1` | `rgba(31,35,40,.12)` | `rgba(1,4,9,.3)` | 卡片投影 |
| `shadow-2` | `rgba(31,35,40,.20)` | `rgba(1,4,9,.45)` | 浮层投影 |

**语义映射（已有，别重复造）**：

| 语义 | 令牌 |
|---|---|
| 只读 / 信息 | `risk-0-*` / `info` |
| 写入 | `risk-1-*` / `warning` |
| 结构变更 | `risk-2-*` / `error` |
| 管理操作 | `risk-3-*` |

**硬规则**：`app.css` 里**不得出现任何颜色字面量**（`TokenParityTest` 已守着），新加的颜色也必须先进 `tokens.json`。

## 8. 交互规范

| 状态 | 规范 |
|---|---|
| 默认 | 底 `bg-elevated`，边 `border`，字 `text-primary` |
| 悬停 | 底 `bg-hover`，字 `text-primary` |
| 按下 | 底 `bg-active` |
| **聚焦** | 边 `accent` 2px + 1px 外扩 —— **每个可聚焦控件都有** |
| **禁用** | 底 `bg-disabled` + 字 `text-disabled` + **保留边框**，**不用 opacity** |
| 加载中 | 按钮内嵌 spinner + 禁用 + 原宽度（不跳动） |
| 危险 | `adb-button--danger` + 二次确认 + 风险徽标 |

**空状态规范**：大标题（`fs-2xl`）+ 一句说明 + **一个明确的下一步按钮**（primary）。
当前只有文字，没有按钮 —— 用户不知道能干什么。

## 9. 明确不做

| 不做 | 原因 |
|---|---|
| ER 图 / 表设计器 | 首版范围外 |
| 传输同步 / 计划任务 / 用户权限 | 首版范围外 |
| 自绘标题栏 | 用系统原生窗口 |
| 插件系统 / AI 面板 | 首版范围外 |
| 主题「跟随系统」的 Windows / Linux 探测 | 已在 `NAVICAT-TODO.md` §9 记为 P7 |
| 矢量图标的**动画 / 插画风格** | 只做统一的单色描边图标 |
