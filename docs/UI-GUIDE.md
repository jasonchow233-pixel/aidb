## 1. 视觉基线

- **原生窗口**：`StageStyle.DECORATED`，不自绘标题栏；macOS 菜单进入系统菜单栏。
- **密度**：正文 **12px**；行高 **dense 19 / compact 20 / normal 21 / comfort 26**，**默认 normal**；
  数据网格 = 列表行高 **+2px**（21/22/23/28，默认 **23**）；对象树 **21px**（`row-tree`）。
  （2026-10-26 用户裁定「保持和 Navicat 一样」，按 Navicat 17 实测改判。）
- **主题**：亮色是评审基准；暗色与亮色共享同一组语义令牌。
- **颜色**：业务 CSS 不写 `#rrggbb` / `rgba(...)`，只引用 `-adb-*` looked-up colors。
  强调色 `#0067B8`（Navicat 实测 `#0078D7`，为 WCAG AA 压暗）。
- **圆角/间距**：**5 档 + pill**：`r-sm` 2 / `r-md` 3 / `r-lg` 4 / `r-xl` 6 / `r-full` 999，外层 ≥ 内层；
  7 档 4px 间距阶梯；页面外边距 16px，工具栏 8px。
- **图标**：**矢量图标**（`io.agenticdb.ui.Icons`，**68** 个 = 59 个 Lucide 源 + 9 个自绘）。
  9 个自绘 = 品牌标 `BRAND` + 圆点 `DOT` + `AI` + **六家厂商数据库图形** `DB_*`（R43-a，见图标约定节）。
  （68 这一档含 R62-a H6-g 新接的五枚「集合」字形 `GROUP_*` —— 从已锁定的 lucide-static v1.61.0 vendor 原件，不是自画。）
  统一 16×16 视框、1.5px 描边；6 档尺寸 **8 / 12 / 14 / 16 / 20 / 26**（dot / badge / label / toolbar / primary / ribbon）。
  颜色由 CSS 的 `.adb-icon` 接管 → 切主题自动跟着变。
  ⛔ **按钮里不许再出现 Unicode 符号**（`IconSystemAuditTest` 守着）。

### 图标约定

**一套图标只表一个意思。** 已知撞车与待统一项：

| 符号 | 问题 | 处理 |
|---|---|---|
| `⚙` | 同时表示“结构”和“设置”（`TabKind.STRUCTURE` / `TabKind.SETTINGS`） | ✅ **已彻底拆开**：`TabKind.STRUCTURE`、数据页「结构」按钮、空态图标都用 `☰`；`⚙` 只剩「设置」 |
| `↻` / `⟳` | 同一个“刷新”有两种字形 | ✅ 统一为 `↻` |
| `✕` / `×` | 同一个“关闭”有两种字形 | ✅ 统一为 `✕` |
| `⌕` / `🔍` | 放大镜用了两个码位，且 `⌕` 的 Unicode 名是「电话录音机」 | ✅ 统一 `⌕` |
| `⌄` | 用下箭头冒充漏斗 | ✅ 换成 `▽` |
| `🔍` `🔑` | 非 BMP 彩色 emoji，与相邻的 `•` 视觉重量不一致 | ✅ 已换单色符号，PK 用 `[PK]` |

**跨平台缺字**：`⚙ ▤ ▦ ⌕ ▇ ⬢ ⇅ ⌷ ◈` 属 Miscellaneous Technical / Geometric Shapes，
Windows 上常见字体可能替换或缺失。这条已经**不再是方向而是现状**：
界面里所有图标都是内嵌 SVG（`icons/lucide/*.svg`，Lucide 静态集 ISC 许可，许可证随目录分发），
没有图标字体、没有位图。

| 颜色从哪来 | 资产里**只标角色**（`data-paint="edge / tone-a / tone-b / tone-c / accent"`），一个色值都不写；颜色一律由 `app.css` 的 `-adb-icon-*` 取自 `tokens.json` | `ColoredIconTest.coloredAssetsDeclareRolesInsteadOfColors` |
| 暗色档 | **不需要第二套资产**：角色吃令牌，令牌跟主题 → 同一张 svg 在两套主题里各自换色 | `IconKindHueTest.theKindHueFollowsTheThemeWithoutASecondAssetSet` |
| 分层顺序 | 自下而上画，**轮廓层（EDGE）收尾**；轮廓与单色同一套 1.5px 粗细口径 | `ColoredIconTest.everyColoredIconKeepsOneEdgeLayerOnTop` |
| 类型色 | ⭐ 「形状 + 颜色」是**一对**线索，彩色档不许删掉其中一条：轮廓层经 `.adb-tree__icon--table .adb-icon-edge` 吃 `-adb-kind-*`，三层 tone 保持中性浅蓝（类型色只走轮廓这一条道） | `IconKindHueTest`（读**计算色**，不读 CSS 文本） |
| 厂商图形 | ⭐ R43-a：**一家一枚、各自不同形**（MySQL 海豚鳍 / PostgreSQL 獠牙 U / SQL Server 六边形宝石 / Oracle 椭圆环 / SQLite 羽叶 / MariaDB 圆球跃身），登记在 `ConnectionCatalog` 的行上 —— 向导磁贴与左侧树从**同一行**取图形与作用域类，所以两处的 MySQL 不会是两种颜色。图形是**同风格自绘标识**，不是商标图标（见素材红线）；品牌色走 `-adb-vendor-*` 令牌（两档各一个值），只落 `tone-c` 那一层，轮廓层仍吃 `-adb-icon-edge` 保可读 | `VendorGlyphTest`（不同形 / CSS 规则 / **两档计算色** / 磁贴作用域）· `SideBarTreeTest.connectionNodesWearTheirVendorGlyph`（断渲染出的 cell，不断节点取值）· `ContrastTest.vendorBrandColorsStandOutAgainstTheBackground`（≥3:1） |
| 集合（分组）字形 | ⭐ R62-a H6-g：**分组行的字形不许和它孩子那枚是同一个**。「Tables」这一行画一个表、下面每行也画一个表 = 父子同形，「这行是集合还是对象」只能靠缩进读。五枚 `GROUP_*`（表集合 / 视图集合 / 函数集合 / 已保存查询 / 连接分组）说的都是「一摞 / 一个容器」，类型由同一行的文字和孩子节点交代；叶子那几枚一个像素没动。⚠️ **集合字形保持单色**：分组节点拿不到对象类型（`iconStyleClass` 按 kind 分色，GROUP 只有一档灰），给它上色等于宣布「集合自成一类对象」，而集合不是对象 —— 所以它们**不进**下面那两张彩色词汇表清单 | `SideBarCollectionGlyphTest`（两个通道：真画出来的路径几何 + 模型上的图标名；另钉「没有彩色资产」）· `IconSystemAuditTest.everyIconIsActuallyUsed` |
| 「本版本未提供」的入口 | ⭐ R62-a H5-i（Q8 拍第②案）：落说明页的功能入口**留在原位、不降位、不变灰**，只加一枚 8px **空心环**（`adb-pending__mark`）。三条规矩：① 环是**不参与布局**的 overlay（`managed=false` + `mouseTransparent`，位置由监听器 `resizeRelocate` 跟着宿主算）—— 包一层容器实测会把同行磁贴撑宽 ±6~7px；② **不用 `-fx-opacity` 压暗**（`FocusRingAuditTest` 守着「不许用透明度藏内容」），也不给 `Region` 写 `-fx-stroke`（Region 不吃 stroke，会静默空转）；③ 实话必须在**点之前**就说：`accessibleText` 与 `Tooltip` 共用 `ribbon.pending` 一个资源键。环只给功能区磁贴，横排按钮那一档只补文案（同一条撑宽理由） | `AppBarTest`（环贴在右上角 + 格子没被挪动）· `TableListPageTest.thePendingAiEntrySaysSoBeforeTheClick` · `RibbonCapabilityAuditTest.thePendingBadgesMatchTheHonestLandingPoints`（挂标集合 ⇔ 落说明页集合） |
| 容器不能挂色 | 分层返回的是 `Group`，它在 JavaFX 里没有任何可声明的绘制属性 —— 把 `-fx-stroke` 打在容器上等于空转。类名挂在容器上，**颜色规则必须写后代选择器**落到子层 | 同上 |
| ⛔ 素材红线 | 竞品（Navicat 等）的位图/图标属**他人版权素材**，一律不许进 `icons/`；像素复刻 ≠ 素材入库 | `ColoredIconTest` 头部注释 + 人工审计 |

**可访问性**：所有图标按钮必须调用 `setAccessibleText("刷新")` 这类文本，
读屏软件才能读出语义而不是读出符号。工厂方法（`SideBar.railButton` /
`navButton`、`ActionRegistry.iconButton`）统一写入，新增控件走工厂即可（4.5-6 ✅）。

**Tooltip 与 accessible text 规则**（4.5-15 ✅）：

1. 图标控件（文本 ≤ 2 个符号字符的 `Button` / `Label`）必须**同时**有 Tooltip 与 accessible text。
2. 豁免只有两种：**容器内已有文字**（图标是陪衬）与**表格单元格内**（内容本身可读）。
3. 门禁：`IconAuditTest` 遍历控件树断言上述规则，新增豁免必须改测试、不允许改代码绕开。

**符号语义唯一性（✅ 4.5-5）**：`IconAuditTest.managedSymbolsMeanExactlyOneThing`
现在会遍历控件树，把受管符号（`⚙` `☰` `↻` `✕` `⌕`）与它们的语义
（去掉符号后的文字 → accessibleText → Tooltip）收集起来，
**同一个符号对应两种语义即失败**。末尾的括号提示（`搜索 (⌘F)`）会被归一化，
避免因为提示键位不同而误报。

**窗口状态记忆**：宽高 / 侧栏宽度 / 折叠态已持久化（`AppShell.saveWindowState`）；
窗口位置 x/y、上次使用的连接、最近打开的对象仍缺失（→ S7）。

## 3. 组件与交互规则

### 3.1 动作与快捷键

- 菜单、工具栏、右键菜单、命令面板共用 `ActionRegistry`，不允许各自判断 enabled。
  **已知例外（4 处）**：侧栏树右键菜单、侧栏导航按钮、工具栏图标按钮、
  标签栏右键菜单仍走独立路径（→ 4.5-8 / 4.5-9 / 4.5-10 / 4.5-29）。
- **动作被禁用时必须给反馈**：`Action.run()` 在 `enabled == false` 时静默 no-op，
  用户点了没反应也不知道为什么（→ 4.5-30）。
- 表格内快捷键：`⌘Z` 撤销、`⇧⌘Z` 重做、`⌘S` 保存、`⌘F` 本页搜索、
  `⌘C` 复制值、`⌥⌘C` 复制 TSV、`⇧⌘C` 复制 INSERT、`⌘A` 全选当前页。
  ✅ **八个都已实现**（`DataGridPage.installShortcuts`）。
- 查询页快捷键：`⇧⌘N` 新建查询、`⌘O` 打开 SQL、`⌘R` 执行选区（无选区时执行光标所在语句）、`⇧⌘R` 执行全部、
  `⌘.` 取消、`⌘E` 执行计划、`⌥⇧F` 格式化、`⌘/` 注释、`⌘S` 保存、`⌘F` 查找、`⌘G` 下一个、`⌃H` 替换、
  **`⌘空格` 补全**（R57-a；候选弹层打开时 `↑↓` 换候选、`⏎`/`Tab` 采纳、`Esc` 关闭，焦点全程留在编辑器）。
- 文本输入框聚焦时，不抢 `⌘Z` / `⌘F` 等编辑快捷键。

### 3.2 数据页

- **只读优先**：视图、无主键表显示只读标记，编辑/新增/删除全部禁用。
- **NULL ≠ 空串**：NULL 显示 `(NULL)`（灰斜体的 `NULL` 与内容为 "NULL" 的文本分不开，见 `UI-VISUAL-SPEC.md` §7.3），空串显示 `""`；右键菜单分别提供“设为 NULL”“设为空串”。
- **主键列是保护区**：单元格编辑路径禁止改主键（`cellEditable` 检查 `definition.primaryKey()`），
  **批量路径同样禁止**（4.5-26 已修）—— 批量「设空串 / 设 NULL」遇主键列整条不生效并给原因，
  普通列仍然可用（门禁钉住这两半，防止把功能一起禁掉）。
- **脏标记**：编辑单元格左侧竖条/淡色底；删除行淡红；新增行淡绿。
- **保存**：先弹 SQL 预览，确认后在单事务执行；失败整体回滚并保留缓冲。
  预览弹窗的默认按钮是**取消**（4.5-27 已修：破坏性按钮用 `ButtonData.OTHER` + `DestructiveConfirm.pinCancelAsDefault`，
  回车不再执行）。保存期间图标换成转圈且**按钮宽度不变**，整排工具栏不会往左抽。
- **取消保存（R61-c）**：`⌘.` 与查询页同一通道，覆盖三种状态 ——
  ① 排在慢加载**后面**还没开始的保存：摘掉票据，SQL 一行都不落库；
  ② 正在写的批量：在**语句边界**停住 —— 自动提交模式下整批在**一个事务**里，中断即整体回滚，库里一行不变；
     用户自己开了事务时只停住剩余语句，已经跑进去的那几条**留在事务里**由用户 commit / 回滚，
     界面不替他决定（撤销也只有反向 SQL / 回滚事务两条既有通道，没有「一键还原」）；
  ③ 取消走 JavaFX 的 `onCancelled` 而不是 `onFailed` —— 用户自己按的 ⌘. 不该看到「保存失败」的错误框。
  关页签同样摘掉在途保存：页签关了，写入不会再发生。
- **撤销保存**：保存成功 Toast 提供“撤销”，执行保存前生成的反向 SQL；有新的未保存编辑时不再提供。
- **批量条**：选中行后出现；复制 TSV / 复制 INSERT / 克隆 / 设 NULL / 设空串 / 删除；
  整批操作只占一个撤销栈位。
- **视图**：本页搜索、隐藏含 NULL 行、隐藏含空串行、只读转置；都不改服务端分页。
- **列**：列头单击排序（Shift 多列，最多 3 级），双击自适应宽度；列宽/顺序/显隐持久化。
- **详情抽屉**：文本 / JSON / Hex / 图片 / 元数据；大字段按 Tab 懒加载；Esc 关闭。
- **导出**：当前页 CSV（UTF-8 BOM）、复制当前页 TSV、复制当前页 INSERT。
- **分页**：`⇤` / `‹ 上一页` / `第 N / M 页` / `下一页 ›` / `⇥` / `跳至页` / 每页档位
  （100 / 200 / 500 / 1000）。`⇤` `⇥` 的 Tooltip 文案是「第一页」「最后一页」。
- **三态**：加载（进度指示）/ 空（说明为什么空）/ 错误（可读原因 + **重试按钮**）。

### 3.3 查询页

- **编辑器**：等宽字体、行号、当前行淡背景；关键字/字符串/数字/注释/参数使用 `-adb-syn-*` token。
- **分栏（R57-g）**：编辑器与结果带之间一条可拖的分隔条，默认比例 **0.463** ——
  这个数是从参照帧逐像素量的（编辑器白带 377px / 分栏总高 814px），原先写死的 0.42 没有出处。
  **只有真的拖过才记住**（在分隔条上按下 → 移动 → 松手，松手时落盘一次）：窗口太矮时
  布局自己夹出来的比例**不写进记忆**，否则第一次在小窗口打开查询页就把意外钉成了永久默认。
  两条最小高钉住「拖到底也不至于什么都看不见」：编辑器 ≥140px（实测行距 16px，留得住 8 行）、
  结果带 ≥205px（帧 `p3-query` 量到「结果页签 31 + Data/Info 30 + 分页条 41 + 列头 26」= 136px
  固定开销，再加 3 行 × 23px）。记忆存 `java.util.prefs` 的 `ui.query.split`（千分比整数），
  全应用一格、不按连接分 —— 它和侧栏宽度同类，是布局习惯，不是数据。
- **风险提示**：编辑器右上角常驻“只读 / 写入 / 结构变更 / 管理”徽标；写操作执行前二次确认并展示 SQL。
- **执行**：`⌘R` **有选区只跑选区**，没选区跑光标所在语句（R57-b）；`⇧⌘R` 跑全部；每条语句一个结果页签。
  实拍见 `docs/screenshots/p3-query-selection.png`：两段语句圈住第二段跑，状态栏回显、结果页签、危险分级三处读的都是**圈住那一段**。
  选区按字面切句，**不往两边扩到语句边界** —— 圈半句就拿到服务端的语法错误，这比把半句悄悄补成整句好发现；
  圈住空白或纯注释时报「选区里没有可执行的语句」，不退回光标那条。
  危险分级、状态栏的 SQL 回显、查询历史全部读**同一份**选中文本 —— 确认框问你的就是真正执行的。
- **结果**：结果集只读表格复用 P2 单元格渲染；消息页显示影响行数；错误页显示可读原因并定位编辑器。
- **取消**：运行中显示取消按钮；取消后丢弃迟到回调，不覆盖新结果。
- **查找替换**：查找栏内嵌在编辑器上方，不弹出独立窗口；替换只作用于当前查询文本。
- **补全（R57-a）**：浮在编辑器光标下方的一张候选列表（类型图形 + 名称 + 所属表副标题），
  实拍见 `docs/screenshots/p3-query-completions.png`（真 MySQL 的 `shop`，候选 = 那把库里的 `orders` / `users` / `v_active_users`）。
  ⚠️ 「贴在光标下面」这句 2026-11-04 之前是**做不到的**：弹层一直开在靠近屏幕左上角的地方（**D-47**，锚点坐标系用错），
  补这一帧画面证据时目视才发现 —— 行为门禁只问候选内容、从不问坐标。
  **只在 `.` 之后自动弹、`⌘空格` 强弹** —— 普通打字不弹（打一半弹上去会糊住正在写的词）；
  字符串 / 注释 / 数字 / 参数里不弹；认不出的限定符**不猜、也不倒出全部**（宁可不弹）。
  词表来自当前库的对象清单 + 逐表列名，两者都在后台懒读，**跑成功一条 DDL 即整块作废重取**；
  加载中弹层底部给一行「正在读取对象清单…」，不假装词表已经全。
- **导出（R57-d）**：范围三档（本页 / 选中行 / 全部结果）× 格式六档
  （CSV / TSV / JSON / xlsx / XML / HTML）。**格式就挂在系统保存对话框的扩展名档上** ——
  不再在界面上搭第二层下拉，同一个决定不给两个入口、两处默认值；文件名后缀跟着同一档换
  （对不上任何导出档的后缀会补上，因为名字承诺 `.txt`、里面是 CSV 会误导下一个打开的人）。
  ⛔ **查询结果没有 SQL(INSERT) 这一档**：结果集没有目标表名，硬写会产出一个只有值元组、
  不能执行的文件 —— 要 INSERT 用导出向导（那边有真表名）。三种范围交**同一套类型口径**
  （JDBC 原始值，不再 `String.valueOf`），所以 JSON 里是 `42` 与 `null`，不是 `"42"` 与 `""`；
  BOM 只给 CSV / TSV（Excel 拆中文靠它，JSON / XML / HTML 多一枚会让严格的解析器报错）；
  写盘一律在后台线程，结果集大时界面不冻。⚠️ 「选中行」能真多选是这轮才修的：
  结果网格原本 `SelectionMode.SINGLE`，菜单写着复数却最多只能导一行。
- **格式化/注释**：格式化只改空白与关键字大小写；注释使用 `-- ` 前缀，支持多行切换。
- **历史**：最近 50 条，去重，保存在 `java.util.prefs`；首版不提供跨设备同步。

### 3.4 结构页

- **五个页签**：列 / 索引 / 外键 / 触发器 / DDL。
- **只读优先**：索引、外键、触发器、DDL 全部只读；视图整体只读。
- **可编辑范围**：仅列——新增列、修改可空 / 默认值 / 注释 / 唯一、重命名列、删除列。
- **危险分级**：改列与删列要两级确认（先展示将要执行的 SQL，再确认高风险）。
- **主键保护**：主键列不能直接删除，提示先调整主键。
- **事务**：结构变更单事务执行，失败整体回滚；SQLite 走整表重建（临时关外键）。
- **联动**：结构变更成功后刷新对象树与所有已打开的数据页 / 结构页。
- **DDL 来源提示**：PostgreSQL 无 `SHOW CREATE TABLE`，DDL 区域必须标注「由内省生成的等价 DDL」。

### 3.5 连接管理页与连接向导

**连接管理页**

- 列表显示：名称（收藏带 `★`）、类型 + 目标（已连接追加“已连接”）。
- 工具条：`＋ 新建连接` / `打开` / `编辑` / `复制` / `删除` / `↻ 刷新`。

**连接向导（两页，900×700）**

| 步骤 | 内容 |
|---|---|
| 1 类型 | **一行 6 张磁贴**（只摆真有驱动的六家，磁贴块在页面中部居中）+ 一行「其它数据库走兼容协议 / URI」的提示 + `New Connection with URI…` |
| 2 属性 | 七页签：常规（`AIDB ⟷ Database` 示意图 + 主机 / 端口 / 库 / 用户 / 密码）· 高级 · 库清单 · TLS · SSH · HTTP · 备注；底部五键（测试连接 / URI… / 上一步 / 取消 / 确定） |

  看着像没做完；`typePageShowsOnlyTheSixDriversItActuallyShips` 把这条钉住。
- 可回退且**不丢输入**；校验错误写在**常驻的错误行**里（第 1 步看不到第 2 步的摘要区）。
- 口令只在保存时写入 `CredentialStore`，`ConnectionProfile` 里不存口令。
- ⛔ 导航按钮（“上一步 / 下一步 / 测试连接”）**不能**放进
  `dialog.getDialogPane().getButtonTypes()`：JavaFX 的 `DialogPane.createButton`

  导航按钮放内容区，只有“保存 / 取消”用原生按钮；“保存”用 `ActionEvent` 过滤器做校验，

### 3.6 反馈

- 加载：骨架/进度指示，禁止 UI 线程阻塞。
- 空态：说明为什么空 + 下一步动作。
- 错误：可读原因 + 重试；危险操作二次确认，默认按钮不是破坏性动作。
- Toast：三档时长 —— 普通 1.8s、带撤销 6s、不可撤销的结果 4s。
- 禁用动作：点了必须给反馈，不允许静默 no-op。

### 3.7 弹窗规范（→ 4.5-27）

**统一入口**：所有「破坏性确认」必须走 `DestructiveConfirm`
（破坏性按钮 `ButtonData.OTHER`、取消 `CANCEL_CLOSE`、`setOnShown` 把默认按钮钉在取消上）。

**默认按钮规则**：

| 弹窗 | 默认按钮 | 状态 |
|---|---|---|
| 删除连接 | 取消 | ✅ |
| 放弃修改 / 放弃并退出 | 取消 | ✅ |
| 结构变更确认（两级） | 取消 | ✅ |
| **保存修改（SQL 预览）** | **取消** | ✅ 已改（`ButtonData.OTHER` + `pinCancelAsDefault`） |
| 新建 / 设计视图（V1/V2） | 创建 · 更新（OK_DONE），**校验不过 `consume`** | ✅ R42：弹窗留在原地，不让用户刚写的查询体被关掉清掉 |
| 删除视图（V3） | **取消** | ✅ 走 `StructurePlanRunner.confirm`（破坏性） |

**其余缺口**（按需补）：

1. 没有统一的「错误详情」弹窗 —— 错误只落在状态栏一行。
2. 没有批量确认汇总页（一次删 500 行只有一行 header）。
3. 没有错误归类（连接断开 / 权限不足 / 不存在 / 超时 / 死锁）。
4. `DialogPane.createButton` 的坑见架构文档 §7.1：导航按钮不能放按钮栏。

**弹窗配色的特异性坑**（R42 帧目视抓到）：`app.css` 里 `.adb-dialog .label` 是 **(0,2,0)**，
裸类 `.adb-error` / `.adb-muted` 只有 **(0,1,0)** —— 于是**弹窗里的校验错误行和提示行全部渲染成正文黑**，
红字只存在于单测里。新建表弹窗同病（它的错误行也是 `.adb-error`），只是那几张帧没拍到错误态。
已补 `.adb-dialog .adb-error` / `.adb-dialog .adb-muted` 两条同特异性、写在后面的规则；
门禁 `ViewDesignerDialogTest.errorAndHintKeepTheirColorsInsideADialog` 同时钉**存在**与**顺序**
（同特异性时后写的才赢）。**给后来人的一句话**：给弹窗里的文字加语义色，别指望裸类名生效。

## 4. 可访问性与键盘

- 所有可点击控件必须可 Tab 到达；表格支持方向键移动焦点。
  ⭐ **第二十六轮起这条有门禁**：`AccessibilityAuditTest` 按场景图前序断言**六区焦点顺序**
  （菜单 → 功能栏 → 侧栏 → 标签栏 → 内容区 → 状态栏，状态栏**零**停靠点）。
- **标签页与对象切面必须键盘可操作**（`←/→` 切换并同步激活、`Enter`/`Space` 确认），
  角色是 `AccessibleRole.TAB_ITEM`；卡片列表是 `LIST_ITEM`。以前它们是纯鼠标的 `Label`。
- ⚠️ **审计类用例不许「没东西可审就通过」**（R42 的教训）：`AccessibilityAuditTest` 里四条用例
  靠双击树节点开出数据页再审那一片子树。TestFX 的 `doubleClickOn` 是两次独立单击，机器压满时
  间隔越过平台连击窗口（500ms），页面根本没开 —— 两条 `lookup(...)` 断言报**假红**，
  另两条走查全树的断言**零违规通过**（假绿，更坏）。现在统一走 `openTableTab(...)`：
  等到标签节点真的出现才继续，三次等不到就失败并写明是哪一格。
- **容器也要有可朗读名称**：`TableView` / `TreeView` / `CheckBox` / `ComboBox` 光有可见文字不够，
  读屏需要 `setAccessibleText`（网格、冻结网格、全选、每行、布尔单元、每页下拉、对象树、对象清单）。
- 禁用态与只读态必须视觉可区分，不能只靠颜色。
- 错误不能只靠 Toast；状态栏或对话框保留可追溯信息。
- 单元格 Tooltip 对截断文本、NULL/空串、BLOB 大小、枚举映射给出完整解释。
- 图标按钮必须有 accessible text（→ 4.5-6），门禁 `IconAuditTest`。
- 对比度：✅ 已有自动检查 —— `ContrastTest`（正文 ≥4.5:1、焦点环 ≥3:1）+ `FocusRingAuditTest`（焦点环规则）；
  见 `docs/UI-VISUAL-SPEC.md` §14。
- **启动耗时是用户体验的一部分**：`StartupTrace` 把「进程启动 → 首屏」分段写进
  `~/.agenticdb/logs/startup.log`，「关于 AIDB」回显本次耗时。⚠️ 当前**冷启动本机实测 5.0–5.6 s**
  （2026-11-04 · macOS + JDK 25 · `scripts/startup-bench.sh` 三次取最坏），未达 < 2s 规格目标、也未达本轮 <3s 阶段目标。
  ⚠️ 这里以前写的「3.5–3.9 s」量于另一台机器（Windows 10 + JDK 27）、且没记读的是两个数里的哪个，不可比，已作废。
  （分段明细看 `~/.agenticdb/logs/startup.log`，逐段耗时是归因的唯一依据；R61-a 新增的
  `shell.demo-db-started` / `shell.demo-db-ready` 两处打点就是用来量「重叠后还在等库」那一段的。）
